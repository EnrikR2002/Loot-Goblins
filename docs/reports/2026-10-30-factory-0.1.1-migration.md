# Factory migration: Loot Goblins 0.1.0 to 0.1.1 — October 30, 2026

First production-game migration through the Factory's own updater. Loot Goblins moved from SYFER Roblox Factory `0.1.0` to `0.1.1` with `scripts/update-game.ps1`. Nothing was copied by hand. No file under `src/` changed, and no gameplay, controls, tuning or authority boundaries changed.

The Factory was refreshed (fetch, checkout `main`, `pull --ff-only`) after PR #6 merged; its `main` equalled `origin/main` at `ed1d608` and `FACTORY_VERSION` read `0.1.1`.

## Migration used

`migrations/0.1.0-to-0.1.1`. It replaces only `Invoke-Checked` in `scripts/common.ps1`, and only when that function is exactly the known 0.1.0 text; otherwise it refuses and changes nothing. The Loot Goblins function matched, so it ran. Updater output:

```
Applying SYFER Factory migration 0.1.0 -> 0.1.1
Updated Invoke-Checked in scripts/common.ps1 (only that function changed).
Updated game metadata to SYFER Factory 0.1.1.
```

Why: the old function broke under Windows PowerShell 5.1 whenever a caller captured a tool's stderr (`2>&1`) with `$ErrorActionPreference = 'Stop'`. The 0.1.1 version shows stderr and lets the exit code decide.

## Finding for the Factory (not fixed here)

The updater rewrote `.syfer/factory.json` through Windows PowerShell 5.1 `ConvertTo-Json`, so the whole file changed in form even though only three values changed: 4-space indent, doubled spaces after colons, `'` for `'`, a blank-lined empty `installedItems`, and CRLF in the working copy. Git normalizes it to LF on commit (`.gitattributes`), so the stored file is LF, but the diff is 62 lines for a three-value change. I left the updater's output as it wrote it rather than hand-editing it. Recorded in `.syfer/outbox/` for the Factory.
